## BR-01: Скролл страницы при каждом ходе в мультиплеере

- **Связанный тест-кейс:** TC-21
- **Приоритет:** высокий (нарушает UX основной функции)
- **Шаги воспроизведения:**
  1. Открыть мультиплеер, создать комнату.
  2. Подключиться вторым игроком.
  3. Сделать ход.
- **Ожидаемый результат:** страница остаётся на месте, доска не двигается.
- **Фактический результат:** страница автоматически прокручивается к низу (к чату).
- **Причина:** `scrollIntoView` в `useEffect` при изменении `room.chat` прокручивал всю страницу, а не контейнер чата.
- **Решение:** заменить `scrollIntoView` на `el.scrollTop = el.scrollHeight`; повесить ref на сам контейнер чата.
- **Коммит:** `cd23da6`
- **Статус:** ✅ Закрыт
- **Исполнитель:** Копыл И.

## BR-02: Таймер мультиплеера обновлялся только после хода

- **Связанный тест-кейс:** TC-22
- **Приоритет:** высокий
- **Шаги воспроизведения:**
  1. Открыть партию в мультиплеере.
  2. Подождать 5 секунд, не делая ход.
- **Ожидаемый результат:** часы уменьшаются каждую секунду.
- **Фактический результат:** часы показывают одно и то же значение, обновляются только после хода.
- **Причина:** сервер вызывал `broadcastRoom(room)` только внутри блока таймаута (когда время доходило до 0), а не каждую секунду.
- **Решение:** вынести `broadcastRoom(room)` в конец каждой итерации `setInterval`.
- **Коммит:** `f43294b`
- **Статус:** ✅ Закрыт
- **Исполнитель:** Копыл И.

## BR-03: AudioContext не запускался при первом ходе

- **Связанный тест-кейс:** TC-04
- **Приоритет:** средний (косметика звука)
- **Шаги воспроизведения:**
  1. Открыть любую задачу.
  2. Сразу сделать верный ход.
- **Ожидаемый результат:** звук хода проигрывается.
- **Фактический результат:** первый ход — без звука, все последующие — со звуком.
- **Причина:** Web Audio API требует user gesture для инициализации `AudioContext`; при первой инициализации контекст был `suspended`.
- **Решение:** в `getContext` добавлен вызов `this.ctx.resume()`, если состояние `suspended`.
- **Коммит:** в основном коде `audio.ts`.
- **Статус:** ✅ Закрыт
- **Исполнитель:** Копыл И.

## BR-04: Некорректная проверка окружения в storage.ts

- **Связанный тест-кейс:** TC-10
- **Приоритет:** критический (ломает сохранение прогресса при тестах)
- **Шаги воспроизведения:**
  1. Запустить `npm test`.
- **Ожидаемый результат:** все тесты проходят.
- **Фактический результат:** 2 из 12 тестов падают (`savePuzzleProgress`, `calculateProgressStats`).
- **Причина:** код проверял `typeof window === 'undefined'`, но работал с `localStorage`. В Node.js `window` нет, поэтому функция сразу возвращала пустой объект и не читала данные.
- **Решение:** заменить проверку `window` на `localStorage`.
- **Коммит:** `650dc40`
- **Статус:** ✅ Закрыт
- **Исполнитель:** Копыл И.
