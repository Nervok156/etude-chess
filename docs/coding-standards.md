# Стандарты кодирования — «Этюд»

## Общие принципы

- **Один модуль — одна ответственность.** Компонент отвечает за рендер, утилита — за логику, стор — за данные.
- **Публичные функции и типы — с JSDoc-комментариями.** Особенно параметры и возвращаемые значения.
- **Сложные участки — с inline-комментариями**, которые объясняют *почему*, а не *что*.
- **Никаких `any` без острой необходимости.** Используем `unknown` + narrowing.
- **Функциональный стиль React:** только функции-компоненты и хуки.

## Именование

| Сущность | Стиль | Пример |
|---|---|---|
| Переменные | camelCase | `activePuzzleId`, `moveHistory` |
| Константы | UPPER_SNAKE_CASE | `STORAGE_KEY`, `MAX_ATTEMPTS` |
| Функции | camelCase | `calcProgress`, `isSlotAvailable` |
| Компоненты React | PascalCase | `PuzzleSolver`, `BotGame` |
| Типы, интерфейсы | PascalCase | `Puzzle`, `PuzzleProgress` |
| Файлы компонентов | PascalCase.tsx | `Chessboard.tsx`, `StatsView.tsx` |
| Файлы утилит | camelCase.ts | `storage.ts`, `stockfish.ts` |
| Папки | kebab-case | `utils/`, `components/`, `data/` |

## Структура файла (TS/TSX)

1. Импорты — внешние → внутренние → типы.
2. Константы уровня модуля.
3. Типы и интерфейсы.
4. Основная логика.
5. Экспорты.

## React

- Пропсы типизируются через `interface XxxProps`.
- `useMemo` и `useCallback` — только когда есть реальная необходимость (дорогие вычисления, зависимости эффекта).
- Один компонент — один файл.
- Побочные эффекты — только в `useEffect` с явными зависимостями.

## Git

- Ветка: `feature/<название>`, `fix/<название>`, `docs/<название>`.
- Сообщение коммита: короткое, в прошедшем времени, с глаголом.
  - ✅ «Добавлен модуль отрисовки доски»
  - ✅ «Починен расчёт статистики по темам»
  - ❌ «правки», «фикс», «update»
- Один коммит — одно логическое изменение.
