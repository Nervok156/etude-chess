## Что проверялось

- Все ли 30 тест-кейсов прогнаны.
- Понятны ли баг-репорты.
- Есть ли шаги воспроизведения у каждого бага.
- Корректны ли статусы (✅ / ❌).
- Реалистичны ли фактические результаты.

## Замечания

### Замечание 1. Все кейсы помечены ✅ без разделения первичного и повторного прогона

- **Где:** `docs/test-protocols.md`, все 30 кейсов.
- **Проблема:** статус «пройден» без разделения на «первичный прогон»
  и «повторный прогон после исправления» делает протокол
  неинформативным. Не видно, какие кейсы изначально падали.
- **Серьёзность:** высокая (влияет на доказательность процесса).
- **Решение:** для TC-04, TC-10, TC-21, TC-22 добавлено явное
  разделение: «Первичный прогон (дни 6-8) — FAIL → BR-XX → исправление
  → повторный прогон (30.09) — PASS».

### Замечание 2. Performance-кейсы не обозначены как AUTO/MANUAL

- **Где:** `docs/test-protocols.md`, TC-26..TC-29.
- **Проблема:** непонятно, это ручной прогон или автоматизированный тест.
  В тексте сказано «замер в tests/performance.test.ts», но статус
  «ручное тестирование» противоречит источнику.
- **Серьёзность:** средняя (путает способ проверки).
- **Решение:** для TC-26..TC-28 явно проставлено **AUTO**,
  для TC-29 — **MANUAL** (автозамер не производился).

### Замечание 3. Версия тестируемого приложения указана нечётко

- **Где:** шапка `docs/test-protocols.md`.
- **Проблема:** указано «коммит 947b685», но после этого были
  коммиты документации. Неясно, тестировалась ли версия кода
  или с учётом документации.
- **Серьёзность:** средняя.
- **Решение:** в шапку добавлено уточнение: «Тестирование проводилось
  на версии кода 947b685. Последующие коммиты (7477384 и др.) содержат
  только документацию, код приложения не менялся».

### Замечание 4. Контекст тестирования раскрыт только в summary, а не в протоколах

- **Где:** `docs/test-summary.md` vs `docs/test-protocols.md`.
- **Проблема:** раздел «Контекст тестирования» с пояснением про
  повторный прогон есть только в summary. Читатель протоколов
  без summary не поймёт ситуацию.
- **Серьёзность:** низкая.
- **Решение:** ссылка на summary добавлена в шапку протоколов.

### Замечание 5. Не указано время прогона performance-тестов

- **Где:** `docs/test-protocols.md`, TC-26..TC-29.
- **Проблема:** performance-значения зависят от загрузки системы.
  Без указания даты/времени прогона результаты не воспроизводимы.
- **Серьёзность:** низкая.
- **Решение:** в каждый performance-кейс добавлена строка
  «Дата прогона: 30.09.2026».
