## Замечания

### Замечание 1. В `git-strategy.md` не были указаны активные ветки

- **Где:** `docs/git-strategy.md`, раздел «История работы с ветками»
- **Проблема:** таблица содержала только слитые ветки. Актуальные
  (`feature/daily-puzzle-placeholder`, `bugfix/format-time-hours`,
  `release/v1.0`) не упоминались.
- **Серьёзность:** средняя.
- **Решение:** в таблицу добавлены три активные ветки.

### Замечание 2. Merge-стиль не был описан явно

- **Где:** `docs/git-strategy.md`
- **Проблема:** не указано, какие ветки мержатся через `--no-ff`,
  а какие — через fast-forward.
- **Серьёзность:** средняя.
- **Решение:** добавлен раздел «Merge-стиль» с таблицей.

### Замечание 3. Тег `v1.0` не на последнем коммите релиза

- **Где:** Git история
- **Проблема:** тег `v1.0` стоит на коммите `9c9d574`, после него —
  исправления `formatTime`.
- **Серьёзность:** средняя.
- **Решение:** тег оставлен на `9c9d574` как «релиз 1.0». Последующие
  коммиты — hotfix'ы, для которых в production следовал бы `v1.0.1`.

### Замечание 4. Ветка `release/v1.0` содержит только один коммит

- **Где:** Git
- **Проблема:** release-ветка содержит только `release: notes версии 1.0`.
- **Серьёзность:** низкая.
- **Решение:** оставлено. В production в release-ветке была бы
  финальная стабилизация.

### Замечание 5. В `CHANGELOG.md` нет ссылок на коммиты

- **Где:** `CHANGELOG.md`
- **Проблема:** нет ссылок на конкретные коммиты или PR.
- **Серьёзность:** низкая.
- **Решение:** для учебного проекта оставлено как есть.
